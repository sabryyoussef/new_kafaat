## 2) حالة الطالب — **منفَّذ (ليس view-only)**

**الحقل الصحيح:** `application_status` — تسمية الواجهة **حالة الطالب**

| القيمة | العربي |
|--------|--------|
| accepted | مقبول |
| rejected | مرفوض |
| under_review | تحت المراجعة |
| cancelled | ملغي |

- على `sabry-test` و `TR_K19`: الحقل **`readonly=False`**
- يظهر في فورم الطالب ويمكن تعديله يدوياً من ملف الطالب
- أيضاً يتزامن جزئياً من بوابة التسجيل (`student.registration`)

**لبس محتمل مع المختبر:** يوجد حقل آخر `training_status` (حالة التدريب) وهو **محسوب و readonly** (New / Currently Registered / Completed). إذا نظر المختبر لهذا الحقل سيظن أن الحالة «للعرض فقط».

### خطوات التعديل (توضيح للمختبر)

1. افتح **الطلاب / Students** → اختر متدرباً.
2. ابحث عن حقل **حالة الطالب** (`application_status`) — ليس «Training Status».
3. غيّر القيمة إلى مقبول / مرفوض / تحت المراجعة / ملغي → احفظ.
4. يمكن أيضاً استخدام فلاتر البحث: مقبول / مرفوض / تحت المراجعة / ملغي.

## 4) آلية الـ Batch أوفلاين — **يوجد شرح**

ليست «مزامنة أوفلاين» منفصلة؛ المقصود التشغيلي عند كفاءات هو **Batch Intake** (استيراد دفعة متدربين من ملف).

**الدليل العربي:**  
`/opt/new_kafaat/docs/op_meeting_nabil/guides/USER_GUIDE_BATCH_AR.md`  
**القائمة:** طلاب → عام / General → **Batch Intakes**

### باختصار

1. **Batch Intake** = عملية الاستيراد (رفع ملف).
2. **Batch (`op.batch`)** = الدفعة الدراسية المرتبطة بمقرر.
3. الملف المدعوم فعلياً في المعالج: **CSV UTF-8** (واجهة قد تقبل Excel لكن التحليل يرفض xlsx برسالة واضحة).
4. المسار: إنشاء Intake → رفع CSV → Validate → اختيار Course + Schedule Batch → Process.
5. بعدها يمكن **Assign to Batch** لربط متدربين موجودين بدفعة.

**لماذا قال المختبر «اشرح»:** الدليل موجود في المستودع لكن ربما لم يُرفق في التعليق / لم يُعرض للمختبر كرابط تسليم.

## 5) توزيع المتدربين على موظفي المبيعات بـ Excel — **منفَّذ في مكان مختلف**

**الحكم:** المنفّذ نفّذ المطلوب عبر موديول الطلاب، **وليس** تخصيص `contact_pool_manager`. المختبر بحث في Contact Pools فتوقع تعديلاً هناك.

| ما طُلب | ما نُفّذ |
|---------|----------|
| Excel → موظفي مبيعات | معالج `trainee.sales.assign.wizard` |
| القائمة | **Students → General → Excel assign to sales** |
| الأعمدة | `id_number` + `staff_login` و/أو `staff_email` |
| الحقل الناتج | `op.student.assigned_user_id` |

**Contact Pools** يوزّع `res.partner` يدوياً/round-robin **بدون Excel** — مسار مختلف.

### لماذا «لا تعمل»؟

احتمالات تشغيلية شائعة (وليست غياب الكود):

1. فتح Contact Pools بدل قائمة الطلاب.
2. رفع CSV بدل XLSX (المعالج يتوقع Excel عبر openpyxl).
3. نقص مكتبة `openpyxl` على السيرفر → UserError.
4. المستخدم بلا مجموعة Sales Manager / صلاحية القائمة.
5. `id_number` أو `staff_login` غير مطابقين في الشيت.

**الخلاصة:** ليس «أُضيف ولم يُنفَّذ»؛ بل **أُضيف في المكان الصحيح تقنياً (الطلاب)** بينما المختبر اختبر **contact pools**.

**ليس غياب إنشاء السجل.** يحتاج Ops: ربط الدورة ببرنامج، أو منح صلاحية رؤية قائمة الدورات العامة.
